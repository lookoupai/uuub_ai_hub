# uuub_ai_hub 踩坑记录

> AI 连接基础设施插件（OpenAI 兼容 + jev 协议适配、槽位路由、用量与预算熔断）。
> 本文件记录开发与真机调试中踩过的坑，供后续维护与二次开发参考。记录日期：2026-10-24/25。

## 1. WellCMS HttpClient 契约（两个致命坑）

### 1.1 headers 必须是字符串数组

```php
// ✗ 错误：关联数组会被 buildHeaders 静默丢弃，请求裸奔（无鉴权头 → 所有中转站 401"无效令牌"）
$headers = ['Content-Type' => 'application/json', 'Authorization' => 'Bearer ' . $key];

// ✓ 正确：字符串数组（与主程序 MeiliGateway 用法一致）
$headers = ['Authorization: Bearer ' . $key];
```

### 1.2 Content-Type 不要手动传

`buildBody()` 检测到 `{` 开头的字符串 body 会**自动追加** `Content-Type: application/json`，且该追加路径绕过 `buildHeaders` 的同名去重。手动再传一份会产生**重复头**：
- Go 系服务（one-api/new-api 中转站）取第一个值 → 侥幸通过；
- FastAPI 系服务（如 TypeSafe/jev）合并值 `application/json, application/json` → 无法识别 → 422 → 插件侧表现为 `answers_missing`。

**结论：HttpJson 只传 Authorization，Content-Type 交给 body 自动推导。**

### 1.3 TLS 约定（受保护，勿改）

所有请求保持 `verifySSL => false`、`caBundle => '/tmp/'`（见根目录 AGENTS.md），集中实现在 `Support/HttpJson.php` 单点。

## 2. 协议与模型行为

- **思考型模型**（deepseek-v4.1-flash 等）：`content` 可为空字符串、正文在 `reasoning_content`，小 `max_tokens` 时必然如此。适配器只把"content 键缺失/非字符串"当协议错误，空串放行。
- **连通性测试用 `max_tokens=16`**：太小（8）思考模型配额不够空转；太大（64）慢源站容易超过网关（如 Cloudflare 100 秒）超时 → 524。
- **慢中转站特征**：实测同一端点 17s~超时波动；HTTP 524 = Cloudflare 等不到源站，属服务方健康问题，重试即可。
- **密钥误带 `Bearer ` 前缀**：用户从文档复制 `Authorization: Bearer sk-xxx` 整段粘贴 → 请求头变成 `Bearer Bearer sk-xxx`。保存时自动剥离前缀（`AiHubSettingsService::validateProvider`）。
- **jev 协议契约**（对齐官方 wrapper，github.com/wuyoscar/jev-skill 的 scripts/jev.py）：
  - 端点：OpenRouter `https://openrouter.ai/api/alpha/decisions` 或 TypeSafe `https://api.typesafe.ai/v1/systemone`（base_url 填完整端点，PHP 直实现 JSON 契约，不用其 Python CLI）
  - 请求：`{model, state, questions: {qid: {type: choice|noul|score, instructions, criteria}}}`，questions 是**按题 ID 索引的对象**
  - 响应：`answers` 为**按题 ID 索引的对象**；choice 答案含 `probabilities`（各候选 0~1，总和≈1）；`status=needs_review` 是协议内置的人审信号（阈值 min_probability=0.8 / min_margin=0.15 可调）
- **日预算默认 0=不限**（参照 new-api 令牌惯例，由使用者按需设置）。

## 3. WellCMS 插件机制备忘

- `config.json` 的 `dependencies` 是**映射**不是数组：`{"uuub_ai_hub": "1.0.0"}`；写数组会被解析成 `0 => 值`，报"依赖扩展 0"。依赖须已安装+启用+版本达标；被依赖的插件受反向保护不可卸载。
- `install.php` 的 `$db` 是 DatabaseInterface（ProxyDriver），**没有 Model 层 `find()`**；可用 `queryOne/query/exec/insert/bulkInsert/upsert/update/delete/count/findTable`。
- AI 工具建的文件默认 root 属主，交付前必须 `chown -R www:www`（否则安装时写 config.json 报 Permission denied，错误前缀"CSRF verification error"有误导性）。
- 改 PHP 后必须后台清缓存（编译缓存 `storage/tmp/classes`）。

## 4. 纯数字 provider 键：保存成功、调用成功、唯独显示"未绑定"（2026-10-26）

### 7.1 三层根因（每一层都单独够坑）

1. `require` 配置文件时，PHP 把全数字的数组键 `'911888'` 规范化为 `int(911888)`；
2. **数组赋值时同样规范化**：`$arr[(string)"911888"] = x` 存进去的还是 int 键——
   PHP 里整型样式的字符串键根本存不住，任何"写入前强转"的修复都是空转（第一版修复就栽在这）；
3. 路由表单渲染用严格比较 `$bound("911888"字符串) === $option['value'](int)` → 永远 false
   → 下拉框无选中项 → 浏览器显示第一个选项"未绑定"。

### 7.2 为什么现象诡异（三条路径只有一条坏）

| 路径 | 机制 | 结果 |
|---|---|---|
| saveRouting 保存 | `isset($providers[$bound])`（键强制转换） | ✅ 一直成功，提示"操作成功"是真的 |
| 运行时取渠道 slotBinding/provider() | isset/数组访问（同上） | ✅ AI 调用一直正常 |
| **表单回显选中态** | `===` 严格比较不做类型转换 | ✗ 永远"未绑定" |

### 7.3 正确修法与错误修法

- ✅ 在**比较处双侧 `(string)` 归一**（AiHubAdminController 渲染 slot options 处，附防再犯注释）；
- ❌ 在 normalizeConfig 里强转键再存——PHP 会再转回 int，无效（已撤销并留注释说明）；
- 语义上"连接标识允许数字开头"没问题，纯数字键今后可正常使用。

### 7.4 排查方法论

- 现象"保存成功但回显丢"先做键类型 `gettype()` 三连：文件 require 后 / 服务返回后 / 渲染处；
- 修复"生效了却没生效"是框架编译缓存（见 §8），不是修复错了；
- 判断执行的是哪份类文件用 `get_included_files()`，ReflectionClass 会指到 LazyLoadingProxy 代理。

## 5. 框架编译缓存：DEBUG=0 下改类"不生效"的元凶（2026-10-26）

- `App\Core\Compile::include()`（Compile.php:193）：**DEBUG=0 时缓存文件存在就直接返回，
  永不检查源文件 mtime**——生产环境改任何 PHP 类源码都不会生效，必须 `Compile::flushCache()`。
- 编译产物在 `storage/tmp/classes/`（含 LazyLoadingProxy 等框架类副本）；views/langs/configs 同理分层。
- flush 后需要一次 `Compile::init()` 引导（任何 CLI 入口或下一个 HTTP 请求）才会重建产物；
  验证修复时**先 flush 再用与生产同款引导跑一遍**，否则测的是旧产物。
- flushCache 以 root 运行会把产物建成 root 属主 → FPM 写入被拒全站 500（2026-10-25 事故，
  bin/sms_pipeline.php 已内置自愈）；flush 后记得 `chown -R www:www storage/tmp`。
- `Runtime::reload()` 是发 SIGUSR1 给 Swoole master 的热重载，**FPM 部署下是 no-op**，
  不要指望它让配置/代码生效。
- opcache（validate_timestamps=1, freq=2s）与 EdgeOne CDN 都曾被列为嫌疑，实测均无辜；
  排查顺序建议：浏览器强刷 → CDN 响应头 → opcache 探针（临时 php 文件输出 ini_get）→ 编译缓存。

## 6. admin 页无 Cache-Control 的既有风险（2026-10-26 观察项）

- 本次"未绑定"排查中 EdgeOne 被排除（/bazaar 三连 MISS），但 admin HTML 响应确实没发 Cache-Control；
  uub_sms_bazaar 的 Mini App 宿主页曾因 EdgeOne 缓存旧 HTML 版本冻结（已加 no-cache 先例）。
  若日后出现"后台改了没变化"类工单，优先核查 CDN 缓存与浏览器缓存，再查 §8 编译缓存。

## 7. §4 全数字键坑复发：写入处 (string) 强转无效，比较处才是关键（2026-10-29）

- v2 升级把槽位下拉改为"连接+模型"双下拉后，911888 绑定的槽位再次全部显示"未绑定"
  （bilibili 显示未绑定是因为用户已把 translate/translate_light 重绑到 911888）。
- 根因与 §4 同源但位置更隐蔽：`$providersJson[(string)$key] = ...` **写入时强转是空转**
  （PHP 数组赋值照样规范化为 int 键），真正出事的是 `foreach ($providersJson as $key => ...)`
  ——**循环取出的 $key 对全数字键还原成 int**，`$key === $boundProvider`（int === string）恒 false。
- ✅ 修法仍然只有一条：**比较处双侧 (string) 归一**（AiHubAdminController providerOptions 构建处），
  option 的 value/text 一并 (string)。运行时 slotBinding/saveRouting 走 isset 不受影响，
  所以 AI 调用一直正常，仅后台回显坏——但这状态千万别点提交（下拉首项是"未绑定"，会把绑定清空）。
- 教训：看到"selected 回显丢失"先 grep 所有 `=== $bound` 式比较；§4 的修复只覆盖了
  当时的渲染点，新增渲染点必须复刻同一纪律。注释写了"双侧 (string) 归一"代码却没强转——
  **注释与代码不一致时以代码为准，review 时专挑这类。**

## 8. datalist 不能当"从清单选择"用：按输入值过滤候选（2026-10-29）

- 默认模型字段初版用 `input + datalist`（选项由 JS 从模型清单同步）。实测点击只显示
  当前输入值本身：**浏览器按输入框现有值做子串过滤**，输入 `agnes-3.0-flash` 时
  `Index-Translate-*` 全部被滤掉，用户以为"只有一个模型可选"。
- ✅ 凡"从已知清单里选一个"的语义一律用 `<select>`（服务端按当前值渲染 selected，
  JS 在清单变化时重建并保留仍存在的选中值）；datalist 只适合"补全建议"语义。

## 9. 决策：不做批量测活 / 自动健康检查（2026-10-29，用户明确）

- 用户拍板**不做「一键测试全部模型」**，也不引入任何定时/自动探测。原因：很多中转站
  不喜欢被测活，批量逐模型发真实调用容易被判定滥用封号。
- 现有边界即为最终形态：唯一的真实调用探测是连接表单里**用户手点的「测试当前模型」**
  （单次、16 token）；「拉取模型列表」是免费 GET /models 元数据请求，不算测活。
  后续维护与 AI 会话不得在无用户授权的情况下新增批量测试、定时测活、自动禁用类功能。
